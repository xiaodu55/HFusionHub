# GraphRAG 复评结论（Batch 10，2026-08-30）

> 复评触发条件（优化路线 P3 约定）：仅当 eval-harness 在多跳/跨文档 case 上显示
> 混合检索不足时才立项重建 GraphRAG。本文档为该次数据驱动复评的记录。

## 复评方法

- **评测轨**：离线确定性轨道（`scripts/eval_offline.py` + 冻结评测集
  `evaluation/suite/cases.jsonl`，220 case，synthetic BM25 索引，零网络依赖、可复现）。
- **焦点分类**：`cross_document`（跨文档问答，30 case）——这是当初 GraphRAG（P7）
  预期提供边际收益的场景。
- **对照组**：现有混合检索通道（向量 + BM25 RRF + 查询分解 DAG，无任何图索引）。

## 结论：**不立项重建 GraphRAG**

1. **边际收益不足**：跨文档场景 Hit@5 已达 100%、Recall@5 达 0.900——多跳召回的
   剩余缺口（~10%）集中在部分相关文档未进 top-5，属于排序问题而非"缺图结构"问题；
   图检索引入的实体抽取/图构建/查询规划成本与该收益不成比例。
2. **历史教训仍有效**：P7 移除时的三个结构性问题（内存图索引重启重建、
   >10k 文档知识库不可用、收益不稳定）与当前单实例/私有部署形态不匹配。
3. **替代路径已在位**：跨文档语义跳接当前由「查询分解 DAG + 自适应检索规划 +
   自反思」承担（产出上述指标）；Batch 9 的 supervisor 模式补充了"遗漏要点"
   二次复核通道。

## 未来重开条件（全部满足才复评）

- nightly/离线评测中 `cross_document` Hit@5 持续跌破 0.85，或 Recall@5 跌破 0.75；
- 复核确认缺口源于"实体关系跳接"而非排序（对比 reranker A/B 数据定位）；
- 候选实现优先评估 LightRAG 式轻量图摘要（而非 P7 的全量实体图），并作为
  feature flag 门控的可选检索通道回归。
