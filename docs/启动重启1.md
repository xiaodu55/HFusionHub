# HFusionHub 启动与重启指南

> 本文用于本地开发环境的启动、重启和常见问题排查。生产部署请同时查看 `deploy/docker-compose.prod.yml` 和 `docs/ENVIRONMENT.md`。

## 1. 前置要求

- Java 17+
- Python 3.11+
- Node.js 20.19+ 或 22.12+
- Docker Desktop / Docker Engine
- MySQL 8.0、Redis 7 通常通过 `docker/docker-compose.yml` 启动

## 2. 准备本地环境变量

PowerShell 示例：

```powershell
$env:MYSQL_ROOT_PASSWORD="replace-with-a-strong-root-password"
$env:MYSQL_PASSWORD="replace-with-a-strong-db-password"
$env:DB_USERNAME="hfusionhub"
$env:DB_PASSWORD=$env:MYSQL_PASSWORD
$env:CALLBACK_SECRET="replace-with-a-long-random-callback-secret"
$env:PYTHON_AI_INTERNAL_TOKEN="replace-with-a-long-random-internal-token"
$env:ADMIN_PASSWORD="replace-with-a-strong-admin-password"
```

这些值必须使用你自己的随机值，不要提交 `.env` 文件。

## 3. 启动 MySQL 和 Redis

```powershell
cd docker
docker compose up -d
docker compose ps
```

当前本地 Redis 没有启用密码认证。`docker/.env.example` 中的 `REDIS_PASSWORD` 只是预留项，等 Redis `requirepass` 和 Java `spring.data.redis.password` 串起来后再作为真实配置使用。

## 4. 启动 Java 后端

```powershell
cd ..\java-backend
$env:DB_USERNAME="hfusionhub"
$env:DB_PASSWORD="<与 MYSQL_PASSWORD 相同>"
$env:CALLBACK_SECRET="<与 Python 相同>"
$env:PYTHON_AI_INTERNAL_TOKEN="<与 Python 相同>"
$env:ADMIN_PASSWORD="<管理员初始化密码>"
mvn spring-boot:run
```

访问地址：

- Java API：`http://localhost:8080/api`
- API 文档：`http://localhost:8080/api/doc.html`

## 5. 启动 Python AI 服务

```powershell
cd ..\python-ai
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:PYTHON_AI_INTERNAL_TOKEN="<与 Java 相同>"
$env:CALLBACK_SECRET="<与 Java 相同>"
$env:DEEPSEEK_API_KEY="<DeepSeek API Key>"
$env:JAVA_BACKEND_URL="http://localhost:8080"
python -m app.main
```

健康检查：`http://localhost:9000/health`

注意：

- `DEEPSEEK_API_KEY` 用于聊天 LLM，不是文档向量化 embedding。
- 当前生产向量化路径需要真实 embedding 服务，建议配置 Ollama：`OLLAMA_BASE_URL` 和 `OLLAMA_EMBEDDING_MODEL`。
- 随机向量降级只允许本地开发或测试使用，需要显式设置 `EMBEDDING_ALLOW_FALLBACK=true`。

## 6. 启动前端

```powershell
cd ..\hfusionhub-frontend
npm ci
npm run dev
```

访问地址：`http://localhost:3000`

Vite 开发服务器会把 `/api` 代理到 `http://localhost:8080`。

## 7. 推荐启动顺序

1. Docker 基础设施：MySQL、Redis
2. Java 后端：执行 Flyway 迁移并提供业务 API
3. Python AI：提供 RAG、Agent、文档向量化
4. 前端：访问和调试页面

## 8. 推荐重启顺序

- 修改数据库、Redis、认证、回调或 AI 服务地址后，重启 Java。
- 修改 LLM、embedding、RAG、内部令牌或回调配置后，重启 Python。
- 修改 Vite 配置或前端依赖后，重启前端。
- 只有 MySQL/Redis 配置变化时才需要重启 Docker 基础设施。

## 9. 本地重置数据库

以下命令会删除本地 MySQL 数据卷：

```powershell
cd docker
docker compose down -v
docker compose up -d
```

重置后重新启动 Java，Flyway 会按 `V1` 到 `V8` 自动重建 schema。以后新增表结构必须创建 `V9+` 迁移文件，不要修改已有迁移。

## 10. 生产部署注意事项

`deploy/docker-compose.prod.yml` 已经配置了容器内服务地址：

- `SPRING_DATASOURCE_URL=jdbc:mysql://mysql8:3306/hfusionhub?...`
- `SPRING_DATA_REDIS_HOST=redis7`
- `AI_SERVICE_URL=http://python-ai:9000`
- `PYTHON_AI_CALLBACK_BASE_URL=http://java-backend:8080/api`
- `LLM_ALLOW_MOCK=false`
- `EMBEDDING_ALLOW_FALLBACK=false`

Helm 模板仍需要补齐等价的 Java 环境覆盖项，尤其是数据库 URL、Redis host、Python 回调地址。补齐前不建议把 Helm 当作完整生产部署方案。

## 11. 常见问题

Java 调 Python 返回 401/403：确认 Java 和 Python 两边的 `PYTHON_AI_INTERNAL_TOKEN` 完全一致。

Python 回调 Java 失败：确认 `CALLBACK_SECRET` 一致，并确认 Java 可从 Python 容器或本机访问。

文档向量化失败：确认 Ollama 可访问且包含配置的 embedding 模型；本地临时测试可以设置 `EMBEDDING_ALLOW_FALLBACK=true`。

Flyway checksum mismatch：本地开发可以使用第 9 节重置数据库；生产环境不要手改 `flyway_schema_history`，应创建新的迁移脚本。
